Skeleton Loader — JS Utility

Smart detection and lifecycle management. CSS still does all visual rendering.

What the JS utility does: two things only — smart detection (finds which children to mark as skeleton bars automatically) and toggling (manages data-st-skeleton attribute values). CSS handles all shimmer rendering in both the CSS and JS approaches. The JS utility is completely optional — include it only when you need it.

CSS Approach vs JS Approach

When to use which — and how they work together

Scenario CSS Approach JS Approach
Simple component, all children shimmer ✓ Perfect — one attribute on parent Works but unnecessary overhead
Some children excluded from shimmer Manual data-st-skeleton="false" on each excluded child ✓ Perfect — smart detection skips them automatically
Large complex component, many exclusions Tedious — many manual opt-outs needed ✓ Perfect — smart detection handles complexity
Staggered reveal across multiple cards ✗ Not possible in pure CSS ✓ Built in — reveal({ stagger: 200 })
Reveal one card at a time as data arrives Manual setAttribute per element ✓ Built in — revealAt(index)
Callback when all elements revealed ✗ Not possible in pure CSS ✓ Built in — onReveal callback
Screen reader loading signal (aria-busy) Developer must set and clear aria-busy manually alongside their own toggle logic ✓ Automatic — aria-busy="true" on init(), "false" on reveal()
Reusable component, no IDs needed ✓ Class or attribute selector ✓ Scans [data-st-skeleton="true"] automatically
Mixed use — CSS some places, JS others ✓ Fully compatible — same attribute, no conflicts

1. Auto-Init — HTML Marks the Parents

Strata.skeleton.init() — finds all data-st-skeleton="true" parents automatically

Developer sets data-st-skeleton="true" on parent elements in HTML. On init() the JS utility scans the document, finds all marked parents, runs smart detection on each one, and marks their leaf children individually. No IDs needed. No extra classes needed. The attribute is the signal. 

<!-- Step 1: Mark parents in HTML — attribute is the signal to JS -->
<div class="card" data-st-skeleton="true">
  <div class="card-img-wrap"><img src="photo.jpg"></div>
  <div class="card-body">
    <h3 class="card-title">Article Title</h3>
    <p class="card-text">Description text here</p>
    <button class="btn btn-primary">Read more</button>
  </div>
</div>

<script>
  // Step 2: Init — JS finds all marked parents and runs smart detection
  Strata.skeleton.init()

  // Step 3: Fetch data
  fetch('/api/article/1').then(data => {
    renderCard(data)

    // Step 4: Reveal — JS sets data-st-skeleton="false" on parent and all leaves
    Strata.skeleton.reveal()
  })
</script>

2. Selector Init — No HTML Attribute Needed

Strata.skeleton.init('.selector') — JS sets attribute automatically

If developer does not want to add data-st-skeleton in HTML, pass a selector to init(). JS finds all matching elements, sets data-st-skeleton="true" on them and runs smart detection. Works with any valid CSS selector — class, attribute, nested, anything. 

<!-- No data-st-skeleton in HTML — JS handles everything -->
<div class="feed-item">
  <div class="feed-avatar"><img src="avatar.jpg"></div>
  <div class="feed-content">
    <p class="feed-name">Alex Johnson</p>
    <p class="feed-text">Just shipped a new feature...</p>
    <p class="feed-meta">2 hours ago · 48 likes</p>
  </div>
</div>

<script>
  // Selector init — JS finds all .feed-item and manages them
  // Sets data-st-skeleton="true" automatically
  // No HTML attributes needed at all
  Strata.skeleton.init('.feed-item-js-demo')

  fetch('/api/feed').then(data => {
    renderFeed(data)
    Strata.skeleton.reveal('.feed-item-js-demo')
  })
</script>

3. Staggered Reveal

reveal({ stagger: 200 }) — cards appear one by one

Staggered reveal makes content feel like it is streaming in rather than popping in all at once. Each managed parent reveals 200ms after the previous one. Pure CSS cannot do this — it requires the JS utility.

4. Reveal At Index — As Data Arrives

revealAt(selector, index) — reveal one element at a time

When data for each item arrives independently — like parallel API calls — reveal each element individually as its data becomes ready. No need to wait for all data before showing any content. 

// Three parallel API calls — reveal each card as its data arrives
const cards = ['/api/card/1', '/api/card/2', '/api/card/3']

cards.forEach((url, index) => {
  fetch(url).then(data => {
    renderCard(index, data)
    // Reveal just this one card — others stay as skeleton
    Strata.skeleton.revealAt('.product-card', index)
  })
})

6. Toggle

Strata.skeleton.toggle() — flip between skeleton and real content

Useful for refreshing content — show skeleton while re-fetching, reveal when new data arrives. Toggle flips between true and false — attribute always stays in DOM, only value changes.

Refreshable Widget

This card can go back to skeleton state when data refreshes.

// Toggle — flips between true and false
Strata.skeleton.toggle('#toggle-card')

// Practical use — refresh pattern
async function refresh() {
  Strata.skeleton.show('#widget')      // back to skeleton
  const data = await fetch('/api/data')
  renderWidget(data)
  Strata.skeleton.reveal('#widget')    // reveal new content
}

7. Check Skeleton State

Strata.skeleton.isSkeleton(element) — check current state

const card = document.querySelector('.card')

// Check if currently in skeleton state
if (Strata.skeleton.isSkeleton(card)) {
  console.log('Still loading...')
} else {
  console.log('Content ready')
}

// Practical use — avoid double-fetching
async function loadCard() {
  if (Strata.skeleton.isSkeleton(card)) return // already loading
  Strata.skeleton.show(card)
  const data = await fetch('/api/card')
  renderCard(data)
  Strata.skeleton.reveal(card)
}

8. Full API Reference

Method What it does
Strata.skeleton.init() Auto-discovers all [data-st-skeleton="true"] parents in document. Runs smart detection on each. Call once on page load.
Strata.skeleton.init('.selector') Manages all elements matching selector. Sets data-st-skeleton="true" on them if not already set. Runs smart detection on each.
Strata.skeleton.show() Sets data-st-skeleton="true" on all managed parents and their detected leaves. No selector = all managed elements.
Strata.skeleton.show('.selector') Shows skeleton on matching managed elements only.
Strata.skeleton.reveal() Sets data-st-skeleton="false" on all managed parents and leaves. Attribute stays in DOM — value changes to false.
Strata.skeleton.reveal({ stagger: 200 }) Staggers reveal — each parent reveals 200ms after previous. onReveal callback fires when all done.
Strata.skeleton.revealAt('.selector', 0) Reveals one specific element by index within a selector group. Others stay as skeleton.
Strata.skeleton.toggle() Flips skeleton state — true becomes false, false becomes true.
Strata.skeleton.isSkeleton(el) Returns true if element is currently in skeleton state.
