@strata-packages/cursorfx v0.0.0

CursorFX

One shared engine, six opt-in presets. Each section below mounts its preset as it scrolls into view and unmounts it on the way out — so what you feel at any moment is exactly one preset, driven by the same engine.

Move your pointer. Scroll down.

How this page started — no script of its own

Trail is already running. Nothing initialised it; these attributes on <body> did, before any script below executed: 

<body data-st-cursorfx="trail"
      data-st-cfx-trail-color="var(--demo-fade)"
      data-st-cfx-trail-count="3"
      data-st-cfx-trail-hover-boost="3"
      data-st-cfx-max-particles="220"
      data-st-cfx-tier="auto">

That is the whole integration for a real page. This one goes further only because it mounts and unmounts presets as you scroll and drives every option from a live control panel — which is what the imperative API is for. Section 10 covers both.

What the engine is doing right now

The RAF loop has not started yet — it starts lazily on your first real pointer event, so a page nobody interacts with never animates. Watch loop in the corner readout flip when you move.

Instance methods

Preset-unique methods live on the object mount() returns. The colour and count sliders above call these, not a remount. 

const trail = CursorFX.mount(Trail)

trail.setColor('#ff2d55')
trail.setParticleCount(6)
trail.unmount()

A colour takes anything CSS takes — hex, hsl(), named colours, a linear-gradient(), or a token holding any of them. Gradients are read for their stops; Trail maps them to particle age, so the first stop sits at the pointer and shades down the tail. This page boots from var(--demo-fade).

Instance methods

Target positions are cached and re-measured on a timer, never per frame — measuring every target every frame is a layout thrash. Electric finds its own targets rather than being handed one by the engine, so it filters data-st-cfx-target itself — the last node above is scoped to Magnetic and never draws an arc. 

const arc = CursorFX.mount(Electric)

arc.refreshTargets()
arc.setColor('#7df9ff')

Raise refreshMs, then shuffle without refreshing — the arcs keep pointing at where the nodes used to be. That is the cache.

6 — CursorMorph DOM · CSS

A dot that morphs into the outline of whatever it is over, borrowing that element's own corner radius.

square-ish hard corners
Every option
color —
—
size 14
radius 999
ease 0.18
padding 6
hideNative true

color defaults to empty, which inherits currentColor — legible on any background without the package defining a colour of its own. hideNative and zIndex are read at mount, so that switch remounts the preset.

Frame-rate independent easing

ease is applied as 1 - (1 - ease)^(dt·60), so the dot feels identical at 60 Hz and 144 Hz. A naive x += (target - x) * ease would move twice as fast on a 144 Hz display.

hideNative hides the OS cursor page-wide. Turn it off if you would rather not bet the page on one element rendering.

Tuning it from CSS, not markup

An instance writes a custom property inline only when it overrides a default — so a stylesheet can retune the effect everywhere it was not explicitly set. 

:root { --st-cfx-reveal-radius: 90px; }
.hero  { --st-cfx-reveal-feather: 140px; }

Drag radius above and inspect the container: the property appears only once it differs from the default.

8 — The particle cap is global

maxParticles is one budget shared by every mounted preset, not a per-preset allowance. Mount Trail and ClickBurst together and they compete for the same slots. Memory is allocated once at init() and never grows: a preset that cannot get a particle drops the emission silently.

mounted: none

Mount Trail and ClickBurst, then click repeatedly — the meter bottoms out and Trail visibly thins. That is the cap working, not a bug.

every mounted preset magnetic only flicker only both

data-st-cfx-target names which presets may react to an element. An empty value means all of them. Mount Magnetic and HoverFlicker together, then hover each of the four above.

Composition

Electric, Magnetic, HoverFlicker and CursorMorph consume no particles, so they layer onto anything for free. Only Trail and ClickBurst draw from the pool. Mounting all six at once is the honest stress test.

9 — The engine

Everything the presets do not have to think about.

Lazy loop

One RAF loop for all presets, started on the first real pointer event and stopped when the last preset unmounts. A page nobody touches never animates.

Tab visibility

Switch tabs and come back — the loop pauses on visibilitychange and resumes. Watch loop in the corner readout.

Reduced motion

prefers-reduced-motion: reduce stops the loop outright, and the CSS neutralises the two effects it drives alone. The engine listens for live changes, so toggling it in your OS takes effect without a reload.

Shared hover hit-test

One elementFromPoint per frame for the whole page, shared by every mounted preset. A second preset adds no hit-testing cost.

One canvas

Created only when a canvas preset mounts, removed when the last one unmounts. A page running only DOM presets never allocates one — confirm it in devtools during sections 4–6.

Device tier

tier: 'auto' detects and reports; it never disables anything itself. This page reads CursorFX.tier() into the corner readout and leaves the decision to you.

Full teardown

destroy() removes every listener, element and attribute the package added — the page returns to exactly its pre-init state. Tear it down, then bring it back.

After destroy, scrolling no longer mounts anything and the readout goes quiet — nothing is left listening.

10 — Configuring it without JavaScript

Everything the control panels above do can be set in markup instead. A real page names its presets, sets their options, and writes no script.

hover me — still driven by attributes 
<body data-st-cursorfx="trail magnetic hover-flicker"
      data-st-cfx-trail-color="#7df9ff"
      data-st-cfx-trail-hover-boost="5"
      data-st-cfx-magnetic-strength="0.4"
      data-st-cfx-hover-flicker-duration="700"
      data-st-cfx-max-particles="300">
Naming presets

data-st-cursorfx takes a space-separated list of preset keys — the folder names: trail, click-burst, electric, magnetic, hover-flicker, cursor-morph. Each still needs its script loaded; a key whose file is missing warns in the console rather than doing nothing quietly.

Setting options

data-st-cfx-<preset>-<option>, using the documented option name in kebab-case — hoverBoost becomes hover-boost, maxArcs becomes max-arcs. Anything you leave out keeps its default.

Values

"true"/"false", or a bare attribute, become booleans. Anything numeric becomes a number. Everything else stays a string. No JSON, no quoting rules.

Engine options

max-particles, z-index, tier, hover-selector and respect-reduced-motion take no preset prefix — they configure the shared engine rather than one preset.

Reaching an instance afterwards

A declarative page never receives what mount() returns, so the engine offers a way back in. This page uses exactly that to adopt the Trail instance its own markup mounted: 

Strata.CursorFX.get('trail').setColor('#0f0')
Strata.CursorFX.get('magnetic').setStrength(0.8)
