11. Transitions

transition · transition-fast · transition-slow · transition-none · ease-* · duration-*

Preset speeds — hover each box to see the difference

transition — 200ms
transition-fast — 100ms
transition-slow — 400ms
transition-none — instant

Easing variants

ease-inease-out ease-in-outease-linear

Arbitrary values

transition-[background-color_0.3s_ease] transition-[transform_0.5s_cubic-bezier(0.34,1.56,0.64,1)] duration-[400ms]

Developer control via CSS variables

/* Slow down all transitions globally */
:root { --st-duration: 500ms; }

/* Speed up one specific component */
.btn-primary { --st-duration: 80ms; }

/* Kill all transitions globally */
:root { --st-duration: 0ms; }

/* Disable on one element */
.my-element { --st-duration: 0ms; }

Strata automatically respects prefers-reduced-motion — all transitions are disabled for users who have requested reduced motion in their system settings.

12. State Management

data-st-visible · data-st-collapsed · data-st-loading · data-st-disabled

All interactive states are driven by data-st-* attributes — never by toggling CSS classes. JavaScript sets the attribute value, CSS handles the visual transition automatically.

Visibility — fade in/out with slight translateY

data-st-visible="true"
data-st-visible="false"
I toggle with a fade!

Collapsed — smooth max-height animation

This content collapses and expands smoothly using CSS max-height transition. No JavaScript animation needed — the data attribute drives it entirely. Add as much content here as you like.

Loading state — 70% opacity, cursor wait, no clicks

Disabled state — 50% opacity, cursor not-allowed, no clicks

JavaScript pattern

// Show / hide with fade
element.setAttribute('data-st-visible', 'false')
element.setAttribute('data-st-visible', 'true')

// Collapse / expand with height animation
element.setAttribute('data-st-collapsed', 'true')
element.setAttribute('data-st-collapsed', 'false')

// Loading state
button.setAttribute('data-st-loading', 'true')

// Disabled state
button.setAttribute('data-st-disabled', 'true')

// Never do this in Strata
element.classList.add('hidden')    // wrong
element.classList.toggle('active') // wrong

13. Theme System

data-st-theme · CSS variable overrides · custom themes · system preference

Built-in themes — use the buttons top right to switch

data-st-theme="light" data-st-theme="dark" data-st-theme="dim"

No data-st-theme attribute → follows prefers-color-scheme automatically. No configuration needed.

Override any CSS variable in your stylesheet

/* Light mode overrides */
:root {
  --st-primary:        #7c3aed;
  --st-border-radius:  8px;
  --st-duration:       300ms;
  --st-font-family:    'Inter', sans-serif;
}

/* Dark mode overrides */
[data-st-theme="dark"] {
  --st-primary: #a78bfa;
  --st-bg:      #0f0f0f;
  --st-text:    #f9fafb;
}

Custom theme — unlimited themes supported

/* Define in your CSS */
[data-st-theme="brand"] {
  --st-primary:   #7c3aed;
  --st-secondary: #6d28d9;
  --st-bg:        #0f0f23;
  --st-text:      #fafafa;
  --st-border:    #374151;
}

/* Switch via JavaScript */
document.documentElement.setAttribute('data-st-theme', 'brand')

14. Custom CSS

Writing custom CSS that works with Strata — no !important needed

How @layer makes custom CSS always win

/* Strata's CSS — inside @layer st-components */
@layer st-components {
  .card {
    padding: 1rem;
    border-radius: var(--st-border-radius);
    background: var(--st-bg);
    border: 1px solid var(--st-border);
    box-shadow: var(--st-shadow-sm);
  }
}

/* Your CSS — outside any layer, automatically wins */
.card {
  padding: 2rem;        /* overrides Strata */
  border-radius: 16px;  /* overrides Strata */
  /* background, border, shadow stay from Strata */
  /* no !important needed anywhere */
}

CSS overrides work property by property. You only override what you explicitly write. Everything else remains from Strata.

Targeting specific instances

/* Option 1 — modifier class */
.card.checkout-card { padding: 2rem; }

/* Option 2 — parent selector */
.checkout-section .card { padding: 2rem; }

/* Option 3 — data attribute variant */
[data-st-variant="checkout"].card { padding: 2rem; }

15. JS / TS Naming Convention

-js suffix for JavaScript · -ts suffix for TypeScript

<!-- Signals this element is referenced in a JS file -->
<div class="modal modal-js" id="main-modal-js"></div>

<!-- Signals this element is referenced in a TS file -->
<div class="modal modal-ts" id="main-modal-ts"></div>

// JavaScript
const modal = document.querySelector('.modal-js')
const modalEl = document.getElementById('main-modal-js')

// TypeScript
const modal = document.querySelector<HTMLElement>('.modal-ts')!
const modalEl = document.getElementById('main-modal-ts') as HTMLElement

This convention is for developer communication only — it has no effect on styling. It signals to anyone reading the code that this element is touched by a script.
